# QtMarkText

**Native Markdown editor × LLM inference bus.**

> 让 Markdown 从「静态排版语法」，进化为「人与模型之间的内容契约」。

QtMarkText 是一款用 C++ / Qt 重写的原生 Markdown 编辑器：以 Qt Widgets 构建外壳，以 WebView2 承载 MarkText 的渲染层，追求打开即读、提笔即写的确定性体验。

但它的终点不止于编辑器。这台机器的目标形态，是**人机协同的内容终端**——向上接入异构算力，向下沉淀可编排的生成流水线，最终让 Read · Write · Generate 在同一棵 AST 上闭环。

---

## 愿景

**向上，统一调度算力。**

本地显卡上的 llama.cpp / Ollama、实验室内网的自建推理服务、公有云的大模型 API——在同一套推理总线（Inference Bus）协议下统一纳管：按任务类型路由模型，以 Schema 约束输出结构，token 级流式回填到光标处。算力在哪里不重要，接口一致才重要。

**向下，沉淀生成流水线。**

意图解析 → 结构化提纲 → 分块生成 → 引用与图表回填 → 差异审阅。技术文档、周报复盘、接口说明、读书笔记、方案提案——这些常用内容类型不再从空白页开始，而是从一次意图声明开始。

**关键在边界。**

模型产出的每一行内容，都以 **diff** 的形态进入编辑器：可预览、可逐条采纳或拒绝、可一键回滚。人握有最终笔权，模型只负责起草。

于是 Markdown 不再只是一种文本格式，而成为一种**可执行的中间表达**（Intermediate Representation）。

## 当前状态

本项目采用 **逐步演进、持续公开** 的开发方式：仓库的第一个提交就是最初的可运行快照，后续每一步改造都以独立 commit 呈现。当前处于 **Stage 1 —— 内核收敛**。

### 已落地

| 模块 | 状态 | 说明 |
| :--- | :--- | :--- |
| **渲染内核** | ✅ 可用 | WebView2 承载 MarkText v0.19.1 渲染层，原生样式未经改动 |
| **编辑与多标签** | ✅ 可用 | 会话恢复、自动保存、最近文件、文件树侧栏 |
| **主题系统** | ✅ 可用 | 33 套主题（浅色 10 / 深色 23）、跟随系统主题、外壳配色逐主题对齐 |
| **国际化** | ✅ 可用 | 9 种语言，含简体中文与繁体中文 |
| **导出** | ⚠️ 部分 | HTML / PDF 通道已通，依赖外部 Pandoc（不随程序分发） |
| **外壳 ↔ 渲染层桥接** | ✅ 可用 | 98 条 `mt::` 消息通道，覆盖菜单路由、文件 IO、偏好同步、导出对话框 |
| **降级渲染** | ✅ 可用 | WebView2 不可用时，回退到纯 Qt 的 Markdown 解析与渲染引擎 |
| **原生窗口** | ✅ 可用 | 无边框窗口 + 自绘标题栏，对齐 MarkText 手感 |

## 路线图

| 阶段 | 主题 | 目标 |
| :--- | :--- | :--- |
| **Stage 1** | 内核收敛 | 完成渲染与编辑闭环，确立文档状态机与 AST 边界 · **← 当前** |
| **Stage 2** | 算力接入 | 落地推理总线，打通本地与远端 Provider 的统一协议与流式回填 |
| **Stage 3** | 编排与治理 | 模板化 Prompt 算子、内容类型库、diff 审阅与版本追溯，交由社区共建 |

**三条能力主线**

| 主线 | 目标 |
| :--- | :--- |
| **渲染内核** | 即时渲染、所见即所得与源码模式共享单一文档模型，零漂移；主题、导出、多标签与会话恢复作为基础设施而非功能点缀 |
| **推理总线** | 本地 / 远端算力统一抽象，按能力（延迟、成本、上下文长度、是否联网）动态路由，支持流式中断、降级与离线兜底 |
| **生成编排** | 意图到提纲、提纲到分块、分块到成文全程可控可回放；产出以 diff 入编辑器，全程留痕、可审、可回滚 |
